# v1.0.0 release preparation

Positioning: **READY WITH LIMITATIONS**, conditional on all critical gates in the
[validation record](sprint-11-validation.md). This is a technical deployment-ready
release, not production OpenShift/3scale certification. No external publication
or release tag is created by the preparation scripts.

## Scope and capabilities

READ, DIAGNOSE, RECOMMEND. The 38 [MCP tools](tool-catalog.md) expose bounded
inventory, topology, 3scale classification, evidence correlation, hypotheses,
non-executable plans, virtual traces, opt-in safe probes and knowledge enrichment.
Evidence is required to promote candidates; INCONCLUSIVE is a valid outcome.
No output establishes a confirmed incident cause merely from topology or metrics.

## Security and deployment requirements

Deny-all defaults; scoped environments and operations, read-only Kubernetes RBAC,
no Secret API access, redacted errors/logs and untrusted external text. External
HTTP requires an explicitly configured credential and exact Host allowlist;
operators provide TLS termination and restricted network access. Shared-token
authentication identifies the configured reader, not individual human users.
Probes are disabled by default and require approved endpoints, CIDRs and permission.
An approved Python image digest, target namespace, image reference, credential
mount and environment-specific configuration are required for deployment.

See [compatibility](compatibility.md), [installation](../installation/README.md),
[runbook](../operations/runbook.md), [security review](security-review.md) and
[limits and contracts](contracts.md). Version authority is `project.version` in
pyproject.toml; installed metadata supplies runtime/system_health. OCI version is
a build argument checked against that metadata; revision/source are build inputs,
never Git calls at runtime. Schema version 1.0.0 is an independently stable contract.

## Known limitations

Kubernetes real: NOT QUALIFIED. OpenShift real: NOT QUALIFIED YET.
3scale real: NOT QUALIFIED YET. Linux image execution: NOT QUALIFIED.
Prometheus is protocol-tested with controlled responses, not a qualified live service.
Snapshots are bounded/non-atomic; names alone never prove 3scale membership.
Redis/DB transport success does not prove application health. Logs/traces have
in-memory sources only. RAG uses local committed Git, lexical retrieval and ephemeral
indexes. There is no SSO/OIDC, HA, durable incident DB, automatic remediation or
guarantee against all secret formats. Operator configuration is privileged input.

## Upgrade, rollback and stability

Retain the previous image/wheel, config and checksums. Install the new artifact in
an isolated environment; validate config offline, smoke system_health, then promote
explicitly. For rollback restore the previous image/wheel and matching configuration;
caches/indexes are ephemeral, no database migration is required. Restart for token
rotation/config changes. See the [runbook](../operations/runbook.md).

Stable tool names, inputs/outputs and configuration schema must preserve compatibility
within v1. Incompatible changes require explicit release notes and a major version
or a versioned schema with migration instructions. No silent removal/deprecation.
Capability maturity is separate from wire-contract stability and live qualification.

## Post-1.0 backlog (not implemented)

Real OpenShift/3scale qualification; SSO/OIDC; HA; additional gateways and telemetry
backends; incident database integration; production RAG hardening; separately
authorized controlled remediation. Current release remains read-only.
